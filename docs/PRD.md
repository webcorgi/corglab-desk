# CORGLAB Desk — Product Requirements Document (PRD) v3.0
- 확정일: 2026-11-10
- 상태: Q1~Q29 확정 / Q30~Q40 운영 기본정책 채택(사용자가 잔여 추천안 일괄 승인). 대외 계약·법무·실제 배포는 미검증
- 저장소: https://github.com/webcorgi/corglab-desk
- 목적: 포트폴리오 실습이 아닌 실제 판매 가능한 B2B 구독형 SaaS
- 문서 원칙: **확정 사항**, **설계 권장안**, **미결정**을 구분한다.

## 1. 제품 정의
홈페이지를 운영하는 기업이 기존 홈페이지에 문의 위젯을 삽입하거나 전용 문의 페이지를 연결하고, 들어온 고객 문의를 AI로 분류·요약하여 직원이 답변 초안을 검토·승인한 후 이메일로 응답하는 고객 문의·견적 관리 SaaS.

### 타깃·가치
- 타깃(확정): 홈페이지를 운영하는 모든 기업(코그랩 제작 고객 포함).
- 가치: 문의 누락 감소, 담당자 처리 시간 단축, 문의 이력 및 처리 현황 확인.
- 1차 제품: AI 문의·견적 관리.
- 후속 확장: AI 실시간 상담, 상담원 연결, 견적·계약 관리.

## 3. 사용 흐름 (MVP)
1. 기업 관리자 가입 → 기업 생성 → 홈페이지/도메인 등록.
2. 위젯 코드 복사 또는 기업 전용 문의 페이지 URL 발급.
3. 홈페이지 방문자가 이름·이메일·문의 내용을 제출; 회사명은 선택.
4. 서버 입력 검증, 스팸 방어, 기업 연결 확인 후 문의 저장(한도 초과 시에도 접수·저장은 유지).
5. 기업별 월 AI 처리 한도(Free 30 / Pro 300) 내에서 AI가 해당 기업의 소개·서비스·연락처·말투를 참고해 문의 카테고리·요약·답변 초안을 생성. 이 분류·요약·초안 생성 묶음의 성공적 처리 1회가 사용량 1건이며, 사용자 재생성은 추가 1건, 수동 수정은 무료, 장애에 따른 동일 작업의 자동 재시도는 중복 차감하지 않는다. 확인되지 않은 가격·납기·계약 조건은 지어내지 않고 담당자 확인 필요로 표시. 한도 초과분은 AI 처리 건너뛰고 업그레이드 안내. AI 장애 시 문의 보존.
6. 관리자/직원에게 화면·이메일 알림.
7. 해당 기업의 **관리자 또는 직원**이 AI 초안을 검토·수정·승인하고 명시적으로 발송할 때만 고객에게 이메일 전송. 승인·수정·발송 이력을 기록.
8. 발송 성공/실패, 시각, 담당자, 상태, 처리 이력 및 사용량을 기업 단위로 조회.

### 사용자·권한 (확정 범위)
- 방문자: 공개 폼으로 문의 등록; 타 고객 정보 조회 불가.
- 관리자: 기업 설정, 도메인/설치 코드 관리, 직원 초대·권한 관리, 모든 기업 소속 문의 조회·처리.
- 직원: 자신이 속한 기업의 문의 조회·상태변경·답변 작성/수정/**승인·발송**. 기업 설정 및 직원 초대 불가. 관리자도 해당 기업 문의의 검토·수정·승인·발송 가능(Q21).
- 한 사용자의 복수 기업 소속 지원 여부는 현재 설계 권장 사항이며 별도 확정 필요.

## 4. MVP 필수 기능과 완료 기준
| ID | 기능 | 완료 기준 |
|---|---|---|
| F01 | 기업 가입·로그인·초대 | 기업 가입, 관리자 생성, 만료 있는 직원 초대, 로그인/로그아웃·권한 분리 |
| F02 | 테넌트 격리 | 모든 조회·수정·발송·할당량에서 로그인 사용자의 소속 기업으로 범위 제한; 다른 기업 접근 차단 테스트 |
| F03 | 설치 코드·링크 | 기업별 스크립트 설치 시 우측 하단 문의 버튼·클릭형 팝업 문의 폼 표시, 기업별 버튼 색상·문구 설정. 별도 문의 링크도 제공. 허용 도메인 검증, 키를 비밀키처럼 신뢰하지 않음. 모바일·키보드 접근성 검증 |
| F04 | 문의 접수 | 필수 필드 유효성, 개인정보 안내 및 필수 동의(정책 확정 후), 중복/스팸 제어, DB 저장 |
| F05 | AI 처리 | 기업별 소개·서비스·연락처·말투 설정 CRUD 및 적용, **공통 5개 유형** 중 1개 분류, 핵심 요약, 주요 요청사항, **명시된 일정·예산**, 추가 확인사항, **긴급도 높음/보통/낮음** 추출. 기업 정보에 근거한 맞춤 답변 초안, 고객 추가 질문, 담당자 확인사항을 각각 생성·저장. 미기재 정보는 추측 금지. **일시 오류는 최대 2회 자동 재시도, 최종 실패하면 담당자 알림·수동 전환, 중복 차감 없음**. 승인 전 고객 자동 발송 금지 |
| F06 | 문의 관리 | 목록·상세·검색/필터·상태·담당자·이력, 페이지네이션 |
| F07 | 알림·발송 | 신규 문의 이메일/화면 알림, **관리자·직원 모두** 기업 소속 및 권한 검증 후 답변 검토·수정·승인·발송 가능. 승인자 ID·시각, 답변 수정 버전, 발송 요청/결과 이력 기록. 승인 없는 발송 금지, 중복 발송 방지·실패 재시도 |
| F08 | 요금/한도 | Free 월 AI 처리 30건/관리자 1명(총 1명), Pro 월 AI 처리 300건/관리자 1명+직원 5명(총 6명). **모든 기업·요금제는 한국시간 매월 1일 00:00 초기화**. AI 최초 묶음 처리 1회 = 1건, 사용자 요청 재생성 1회 = 추가 1건, 수동 편집 0건, 시스템 자동 재시도 중복 차감 금지. 한도 초과 시 문의 저장·수동 처리 유지, AI 처리 중단과 안내. 과금 자동 증가 없음 |
| F09 | 운영 | HTTPS, 안전한 비밀정보 관리, DB 백업·복구 검증, 모니터링/로그, CI/CD, Docker 운영. **자사 기업용 문의·AI 사용 현황판**과 **CORGLAB 전용 전체 기업 AI 처리 성공률·오류·API 비용 현황판**을 분리하고 권한 검증 |
| F10 | 사용자 검증 | 외부 기업 1곳 이상 온보딩, 실제 위젯 접수→AI→담당자 승인→이메일 발송 확인 |

## 6. 기술 아키텍처 (설계 권장안, 현재 저장소 기반)
- 프론트: React 19 + Vite / 관리자 웹 + 우측 하단 문의 버튼·팝업 위젯(기업별 색상·문구 설정) + 별도 호스팅 문의 페이지
- API: Java 21 + Spring Boot 3.5 + Spring Security + Bean Validation
- DB: PostgreSQL 17 + Flyway SQL 마이그레이션
- 비동기: Redis 기반 작업 큐 또는 DB outbox + 워커 (구현 및 라이브러리 결정 전)
- AI(확정 Q16·Q18·Q19·Q20): 기업별 소개·서비스·연락처·답변 말투를 설정하고, 문의를 공통 5개 유형으로 분류, 요약·주요 요청사항·명시된 일정/예산·추가 확인사항·긴급도 3단계를 구조화한 뒤 **확인된 기업 정보에 근거한 맞춤 답변 초안 + 고객에게 할 추가 질문 + 담당자 내부 확인사항**을 구분하여 생성. 시스템/기업 설정/고객 문의를 분리하고 기업 간 AI 설정이 섞이지 않게 검증. 미확인 가격·계약·납기 등은 지어내지 않으며 담당자 승인 전 외부 발송 금지. OpenAI API는 서버에서 호출(모델·비용 상한 설정 가능하도록 분리). FAQ·PDF 기반 검색은 후속 단계.
- 이메일(확정): **Resend**. Spring Boot 서버에서 Resend API 사용; API 키는 서버의 비밀 설정에만 저장. 신규 문의 알림, 담당자가 승인한 답변 발송, 발송 이력/재시도/중복 방지 필요. 발신 도메인·주소/발송량·플랜은 미확정.
- 인프라(확정): 초기 **Oracle Cloud Always Free Compute + Docker Compose**, 이용자 증가·성능 부족 시 **AWS Lightsail + Docker**로 이전. 리버스 프록시 + HTTPS + 서버 외부 비밀값 관리 적용.
- 이식성(설계 권장): ARM(Ampere A1)/x86 환경 모두 지원하는 컨테이너 이미지 사용, 환경변수·볼륨·백업 정책 분리, PostgreSQL 논리 백업/복원 및 복구 리허설, DNS 변경으로 서버 이전 가능하도록 구성.
- OCI 주의(운영 제약): Always Free VM은 홈 리전에서만 생성 가능하며 재고 부족으로 인스턴스 생성이 실패할 수 있음. 유휴 인스턴스 회수 가능성이 있으므로 외부 백업·모니터링 필수. 무료 인스턴스 사용 가능 여부·최종 구성은 실제 계정에서 확인해야 함.
- CI/CD: GitHub Actions, 단위/통합 테스트 후 이미지 빌드·배포
- 데이터 보안: 인증 사용자의 기업 소속을 서버에서 조회(클라이언트 tenant_id 신뢰 금지), 모든 DB 쿼리 기업 단위 제한, 권한 테스트, 접근 기록 최소화. **CORGLAB 플랫폼 운영자 역할**은 일반 기업 ADMIN과 분리하고 운영 현황 통계에만 필요한 최소 권한을 부여.
- **현재 저장소 코드 상태:** 로컬 개발용 Basic 인증, 단일 설정 tenant_id, 기초 문의 폼/API/분류; 다중 기업 SaaS, 위젯, 초안, 알림, 결제, 실제 배포는 미완료.

## 13. Q17 AI 사용량 정책 (확정)
- 단위: 고객 문의별 **AI 분류·요약·답변 초안 생성 묶음 1회의 성공적인 처리 = 1건**.
- 사용자가 명시적으로 **AI 다시 생성**을 요청해 새 초안 생성에 성공하면 **추가 1건** 차감.
- 직원의 수동 편집·검토·승인·발송은 AI 사용량에서 차감하지 않음.
- 시스템 오류·타임아웃·큐 재시도·중복 작업 전달에 따른 **동일 AI 작업 자동 재시도는 중복 차감하지 않음**.
- 월 무료 30건 / Pro 300건을 소진하면 이후 고객 문의는 계속 접수·저장하고 AI 생성만 중단하며 업그레이드 안내.
- **권장 구현**: ai_jobs에 요청별 고유 작업 ID/재시도 상태를 저장하고 usage_events에 중복 방지 키(기업+작업 ID)를 유일하게 지정. 성공 상태 확정과 건수 차감을 DB 트랜잭션으로 처리하고, 경쟁 요청 시 한도 초과 실행을 방지하는 동시성 검증 테스트 추가.
- **Q24 확정**: Free/Pro 공통 한국시간 달력월 기준, 매월 1일 00:00 초기화.
- **추가 미결정**: 실패/부분 성공의 청구 판단, AI 재생성 최대 횟수, 처리 중 사용량 예약/확정·월 경계 작업 정책. 이 항목들은 Q17·Q24 결정과 구분한다.

## 14. Q18 AI 문의 분류 정책 (확정)
- 1차 서비스에서는 모든 기업이 **공통 5개 유형** 사용: **견적·구매**, **일반 문의**, **기술·서비스 지원**, **제휴·협업**, **기타**.
- AI 분류 결과는 위 유형 중 정확히 하나. 의미가 분명하지 않거나 여러 유형과 겹치면 무리하게 추측하지 않고 **기타**로 분류하는 것은 설계 권장안(확정되지 않은 예외 정책).
- 분류 결과를 문의 레코드에 저장하고 관리자 목록 필터·통계에서 동일한 유형을 사용. 안정적인 내부 코드(예: quote_purchase/general/support/partnership/other) 사용은 기술 설계 권장안.
- 현재 로컬 MVP의 옛 분류 코드(quote/support/partnership/other)는 Q18과 다르므로 개발 시 스키마/기존 데이터 호환·이관, 결과 검증 및 분류별 테스트 필요. 현재 구현 완료가 아님.
- 기업별 분류 추가·수정 및 개별 정의는 **후속 확장**으로 두며 이번 MVP에서 제외.
- **세부 미결정:** 다중 목적 문의의 우선 분류 기준, 관리자 수동 재분류 권한, 긴급도 판정의 구체적 기준/신뢰도/담당자 수동 변경 정책(Q19는 분석 항목과 긴급도 3단계를 확정).

## 15. Q19 AI 상세 분석 정책 (확정)
- 필수 결과: **문의 유형(Q18의 공통 5개)**, **핵심 요약**, **주요 요청사항**, **고객이 명시한 희망 일정**, **고객이 명시한 예산**, **추가 확인사항**, **긴급도(높음/보통/낮음)**.
- 고객 문의 또는 확정 기업 정보에서 확인할 수 없는 일정·예산 등은 **미기재(null)**로 두고, 금액·기한을 추정하거나 임의로 생성하지 않는다.
- 긴급도는 AI의 **참고 판단**이며 직원이 최종 판단한다. 긴급도에 따른 별도 이메일 경보나 자동 담당자 배정은 아직 확정하지 않음(Q19의 B 선택).
- 권장 구조: category(코드), summary, requests(문자열 배열), requested_deadline(nullable), stated_budget(nullable), clarification_questions(문자열 배열), urgency(high/normal/low). 출력 JSON은 서버에서 값/길이·타입 검증하고 실패 시 수동 처리 가능하도록 보존.
- 권장 테스트: 일정/예산 미기재, 여러 요구사항이 섞인 문의, '급해요' 같은 모호한 표현, 금액·날짜 형식 변형, AI가 가격을 허위로 만들려는 사례.
- **미결정:** 긴급도 구체 판정 기준과 수동 수정 방식, 분석 결과에 근거 문장 표시 여부, 담당자 특별 알림 및 자동 배정 여부(후속 선택 가능).

## 16. Q20 AI 답변 초안 정책 (확정)
- AI는 해당 기업에서 설정한 소개·서비스·연락처·답변 말투 및 고객의 원문에 근거하여 **기업 맞춤 답변 초안**을 만든다.
- 답변 가능한 부분은 직접 설명하고, 답변에 필요한 고객 정보가 부족하면 **고객에게 물어볼 추가 질문**을 초안에 자연스럽게 포함한다.
- 가격·납기·계약·가능 여부 등 사실 확인이 필요한 사항은 추측하지 않고 **담당자 확인사항**으로 별도 구조화해 관리자 화면에 표시한다. 이 내부 확인사항은 고객에게 그대로 전송하지 않는다.
- 결과 데이터 권장 구조: `reply_draft`(고객에게 보낼 후보 문장), `customer_questions`(추가 질문 목록), `staff_review_items`(내부 확인사항), `source_context_version`(기업 설정 참조 버전). 정확한 JSON 스키마·필드 수·길이는 구현 설계 시 결정.
- 직원이 답변 초안을 확인·수정·승인한 뒤에만 Resend로 발송한다. **AI 단독 자동 발송은 금지**(Q4·Q7 유지).
- AI가 만든 답변은 사실 확인 완료를 의미하지 않는다. 정보가 없는 경우 보수적으로 안내하거나 고객 추가 질문을 제안한다. 기업별 정보가 누락됐더라도 문의 접수 자체는 유지한다.
- 품질 테스트: 기업별 설정 격리, 가격·일정·계약 조건 허위 생성 방지, 고객 대상 질문과 내부 확인사항 분리, 개인정보 불필요한 노출 방지, 승인 전 이메일 미발송.
- **Q21 확정**: 관리자·직원 모두 검토·수정·승인·발송할 수 있으며 승인자·수정·발송 이력을 기록한다.
- **Q22 확정**: AI 일시 오류는 최대 2회 자동 재시도하고 최종 실패 시 담당자 알림 및 수동 처리. 시스템 재시도는 중복 차감 금지.
- **미결정(Q23 이후)**: 내부 확인사항 필수 해결 조건, 초안 길이/문체 세부 프리셋, 재시도 간격·타임아웃 등 운영 상세값. 확정 범위를 넘어 단정하지 않는다.

## 17. Q21 답변 승인·발송 및 감사 이력 (확정)
- 기업에 소속된 **ADMIN 및 STAFF 모두** 기업 내 문의의 초안을 **검토·수정·승인·발송**할 수 있다. 기업 관리자 전용 최종 승인 단계는 두지 않는다.
- 실제 발송은 **사용자의 명시적인 발송 동작**에서만 시작한다. AI 처리 성공이나 초안 생성만으로 고객에게 자동 발송하지 않는다.
- **필수 감사 이력**: 누가(사용자 ID·소속 기업) 언제 어떤 초안 버전을 수정했는지, 수정 전후 버전/변경 내역, 승인자 및 승인 시각, 발송 요청자·발송 시각·발송 상태·Resend 결과(민감정보는 최소 기록).
- 동일 기업의 권한 있는 관리자·직원만 검토/승인/발송 가능하도록 서버 측 기업 소속과 권한을 검사한다. 다른 기업 문의를 승인/발송하거나 이력을 읽는 요청은 거부해야 한다.
- **권장 구현**: 초안 버전 변경 후 이전 승인 효력 자동 만료, 발송 시 승인된 버전 일치 확인 및 멱등성 키로 중복 발송 방지, DB 트랜잭션으로 상태·감사 로그 기록. 위 방식은 구체 구현 권장사항으로 별도 테스트 필요.
- **미결정**: 담당자 확인 필요 항목이 남아 있을 때 발송 차단 또는 경고만 할지, 이미 발송한 답변 재발송 정책, 변경 이력 보존 기간의 세부 기준.

## 18. Q22 AI 실패 대응 정책 (확정)
- 고객 문의는 **AI 실행 전에 DB에 먼저 저장**하고, AI 처리 실패 여부와 관계없이 원본을 보존한다.
- 네트워크 오류, 일시적인 서버 오류, 요청 제한(429), 타임아웃 등 **재시도로 복구 가능한 AI 오류**는 최초 실행 이후 **자동 재시도 최대 2회**(즉, 총 최대 3회 시도)로 제한한다.
- 인증·권한 오류, 잘못된 요청 형식 등 재시도로 해결되지 않는 오류는 무의미하게 반복하지 않고 **즉시 실패 처리**한다(기술 설계 권장안).
- 재시도를 모두 소진하거나 복구 불가능한 오류로 실패하면 작업을 **수동 처리 필요**로 표시하고, 담당자에게 알림을 보내 직원이 직접 답변을 작성할 수 있도록 한다. 담당자 알림은 Q7의 이메일+관리자 화면 알림 채널을 따른다.
- Q17 준수: 동일 작업의 자동 재시도·큐 중복 전달로 **AI 사용량을 중복 차감하지 않음**. 정상적으로 완료된 AI 묶음 처리에 한해 1건 확정. 실패한 처리에는 차감하지 않음.
- **구현 권장안**: 작업 ID/기업 ID/문의 ID/시도 횟수/상태(pending, processing, retrying, succeeded, manual_required)/최종 실패 원인 코드/재시도 시각을 저장하고, 중복 작업 실행 차단·지연 재시도·장애 알림 테스트. 개인정보·API 응답 원문은 에러 로그에 불필요하게 남기지 않는다.
- **추후 결정**: 자동 재시도 간격·최대 타임아웃, 오류 유형별 세부 정책, 일부 결과만 생성된 경우 성공/실패 판정, 수동 전환 후 담당자의 명시적 재실행 가능 여부.

## 19. Q23 AI 운영 현황판 범위 (확정)
- **기업 관리자·직원용:** 본인 소속 기업의 문의 접수 및 처리 현황, AI 작업 처리 중/성공/실패·수동 전환 현황, 월 AI 사용량과 잔여 건수를 표시한다. 기업 간 통계·문의 데이터 노출 금지.
- **CORGLAB 플랫폼 운영자용:** 전체 기업의 AI 처리 성공률, 오류 발생 현황, 기업별 AI API 비용을 확인하는 별도 운영 현황판 제공. 개별 기업 ADMIN/STAFF는 이 화면에 접근 불가.
- **비용 추적 권장안:** 모델·시점·입출력 토큰 사용량·처리 비용 추정값·작업 ID를 기업별로 집계. 공식 청구 금액과 추정치가 다를 수 있으므로 화면에서 구분한다. 카드 결제액과 AI API 비용은 서로 다른 지표.
- **보안 권장안:** 플랫폼 운영 현황은 최소 필요 범위의 통계/장애 코드 중심. 문의 원문·답변 본문은 운영 현황판에서 기본적으로 노출하지 않는다. 플랫폼 운영자 신원 확인·접근 감사 로그 적용.
- **후속 확장:** 오류 급증·API 비용 임계치 자동 알림. Q22에서 확정된 **개별 AI 작업 최종 실패 시 담당자 알림**은 현 단계 유지하며, Q23의 전사적 자동 경보 도입과 구분한다.
- **세부 미결정:** 성공률 분모(작업 단위/시도 단위), 기간별 조회/시각화 범위, 비용 통화 및 환율, 플랫폼 운영자 수·역할 등 상세 화면 설계. 모두 Q23 확정 기능 범위와 분리한다.

## 20. Q24 월 AI 사용량 초기화 정책 (확정)
- **Free/Pro 모두** 한국시간(`Asia/Seoul`) 기준 매월 **1일 00:00**에 새 월 한도를 적용한다. 기업 가입일 또는 Pro 카드 결제 갱신일과 무관하다.
- 월 AI 사용량은 기업별로 해당 한국시간 달력월에 해당하는 사용량만 집계한다. 권장 구현은 `[해당 월 1일 00:00, 다음 달 1일 00:00)` 구간(종료 시각 미포함)으로 기록·조회하고, DB에는 UTC 시각을 저장하되 구간 경계는 KST로 계산한다.
- 과거 사용 기록은 삭제하지 않고 월별로 보존한다. '초기화'는 새로운 월의 할당량을 제공하는 정책이지, 고객 문의나 기존 AI 사용 기록을 삭제한다는 의미가 아니다.
- 동시 요청이 월 사용량을 초과하지 않도록 기업·월별 원자적 사용량 확정 및 고유 작업 ID로 중복 차감 방지를 권장한다(Q17 연계).
- **추가 미결정**: 월말에 시작해서 다음 달에 성공한 작업의 귀속 월, Pro 중도 가입·변경 시 즉시 사용량 배정, 결제 갱신일과 한도 기간이 달라 생기는 표시/안내 규칙.

## 21. Q25 요금제별 계정 수 정책 (확정)
- **Free**: 기업 관리자 1명만 사용할 수 있음. 기업 내 전체 사용자 정원 **1명**으로 직원 초대 기능은 비활성화.
- **Pro**: 기업 관리자 **1명** + 초대 가능한 **직원 5명**. 기업 내 전체 사용자 정원 **6명**. 직원 초대/권한 관리 기능은 기업 관리자에게만 허용(Q5).
- 정원 검증은 초대 수락뿐 아니라 직원 초대 생성·재전송·계정 활성화 시에도 적용하고, 한 기업의 다른 사용자가 동시 초대할 때 정원 초과가 없도록 서버 측 검사 및 DB 동시성 테스트를 권장한다.
- **Q28 확정:** Pro→Free 전환 즉시 직원 계정은 구독 사유로 정지되어 로그인 및 문의 접근이 차단되고, 계정·작업 이력은 보존된다. Pro 복구 시 구독 때문에 정지됐던 직원은 자동 활성화한다. 기존에 관리자가 별도로 정지한 직원까지 자동 활성화하지 않는 것은 보안상 권장 사항이다. 초대 대기 처리 등은 별도 세부 설계.
- **미결정**: 추가 관리자 허용 여부, 추가 직원 좌석 구매, 관리자 계정 양도, 구독 하향 시 초과 직원의 비활성화 우선순위.

## 22. Q26 토스페이먼츠 카드 정기결제 (확정)
- 결제 제공사는 **토스페이먼츠(Toss Payments)**로 고정하며 중간 결제 통합 서비스 없이 **Spring Boot 백엔드에서 직접 연동**한다.
- 기업 관리자가 Pro를 신청하면 토스페이먼츠의 공식 카드 등록·빌링키 발급 절차를 통해 결제수단을 등록하고, 서버가 정기 청구/결과 확인/구독 상태 반영을 수행한다.
- **비밀키·빌링키는 브라우저와 공개 GitHub에 노출하지 않는다.** 카드번호·CVC·민감한 카드정보를 CORGLAB Desk가 직접 저장하지 않는다. 빌링키를 보관한다면 암호화·접근권한·변경/폐기 절차를 마련한다.
- 성공/실패 결과, 결제 시각, 금액, 청구 대상 월·계약 상태를 추적하고 네트워크 재시도/서버 재시작에 따른 중복 청구를 막는다. 실제 API 연동 계약·심사·지원 기능은 토스페이먼츠에서 별도 확인해야 한다.
- 유료 구독을 시작하기 전에 실제 계약·심사, 테스트 결제 검증, PG 측 정기결제 요건을 충족해야 한다. **선정은 확정, 연동·계약·실서비스 승인 여부는 미완료**.
- **Q27 확정**: 실패 후 7일간 Pro 유지, 최대 2회 자동 재시도, 끝까지 실패하면 Free 전환 및 고객 알림.
- **Q28 확정:** Free 전환 즉시 직원 접근 정지, 계정·이력 보존, Pro 복구 시 자동 활성화(직전 C 선택은 철회).
- **Q29 확정**: 자발적 해지 시 다음 자동결제 중단, 이미 결제한 기간 종료 후 Free 전환. 아래 Q30~Q40 권장 기본정책도 사용자가 일괄 채택(법무·공급사 확인 필요).

## 23. Q27 카드 정기결제 실패 대응 (확정)
- **결제 실패 시각부터 7일간 Pro 기능을 유지**하는 유예 상태로 전환하고, 결제 실패 사실 및 카드 확인·변경 안내를 기업 관리자에게 전달한다.
- 유예 기간 안에 **자동 결제 재시도는 최대 2회**(최초 정기 청구 시도는 별도) 실행한다. 재시도 성공 시 Pro 상태를 유지하고 결제 성공 및 복구를 기록한다.
- 두 번의 자동 재시도를 포함해 정상 납부가 이뤄지지 않으면 **7일 유예 기간이 끝난 뒤 Free로 전환**하고 기업 관리자에게 알린다. 유예 중 조기 포기하거나 7일 전에 Free로 자동 전환하지 않는다.
- **문의와 기존 이력은 삭제하지 않는다.** Q28에 따라 Free 전환 즉시 기존 직원 계정의 접근을 정지하고, 구독 복구 시 계정·이력을 유지한 채 자동 활성화한다. 기업 관리자 1명은 Free로 계속 이용한다.
- **권장 구현**: subscription status(active, past_due, free), grace_until, failed_at, retry_count, billing_attempts, provider_transaction_id, transition_reason를 저장한다. 청구 주기별 중복 요청 방지, 성공/실패 도착 순서가 뒤집힌 경우 처리, 중복 알림 방지, 유예 종료 일괄 처리 및 테스트가 필요하다.
- **미결정**: 재시도 2회의 정확한 날짜/시각과 정책상 재시도 불가능 오류 처리, 수동 카드 변경 후 즉시 재결제 방식, 결제 기준일·취소·환불 처리. 결제 사업자 실제 승인 및 API 규격 확인은 별도 과제다.

## 24. Q28 Pro→Free 직원 계정 정책 (최종 확정: A)
- Q28의 앞선 C(Free 전환 후 7일 직원 읽기 전용) 선택은 **철회**하고, 최종 사용자 선택 **A**를 적용한다. **Free 전환 이후 별도의 직원 읽기 전용 유예기간은 없다.**
- **Pro→Free 전환 즉시** 관리자 1명을 제외한 직원 최대 5명 계정의 접근 권한을 자동 정지한다. 정지된 직원은 로그인 및 기업 문의·답변·관리 페이지 접근이 차단된다.
- 직원 계정, 소속 기록, 수정·승인·발송 감사 이력 및 기존 문의 데이터는 **삭제하지 않고 보존**한다(기존 개인정보 보존 정책 준수).
- 기업이 **Pro 결제를 복구하면 요금제 때문에 자동 정지된 직원 계정은 자동 활성화**되어 기존 업무를 재개할 수 있다.
- **보안 권장 구현:** 구독 사유 정지(BILLING_SUSPENDED)와 관리자 수동 정지(ADMIN_DISABLED)를 별도 상태로 보관하여 Pro 복구 시 관리자에 의해 별도로 차단된 계정은 자동 복구하지 않는다. 기존 세션·토큰은 정지 시 무효화하고 모든 API 권한은 서버에서 확인한다.
- **검증:** 결제 유예 7일 중 직원 정상 접근(Q27), 유예 만료로 Free 전환되는 순간 직원 접근 차단, Free 관리자 접근 유지, 데이터/이력 보존, 재결제 후 정상 활성화, 수동 정지 계정 잘못 활성화 방지, 중복 결제 이벤트 안전 처리.
- **추가 미결정:** 미수락 직원 초대의 처리, Pro 복구 전 직원 계정 삭제 요청, 요금제 전환과 동시 진행되는 직원 요청 처리의 세부 규칙.

## 25. 3차 인터뷰 일괄 마무리: Q29~Q40 운영 기본정책 (2026-11-10)

사용자가 "나머지는 다 니 추천대로 진행"이라고 요청하여, Q29는 기존 질문의 **추천 B**로 확정하고 Q30~Q40은 별도 질문 없이 **실무 운영을 위한 권장 기본값**으로 채택한다. 이는 사용자에게 이미 개별적으로 제시된 모든 질문의 승인을 뜻하지는 않으며, **실제 계약·법무·운영 검증 없이 상용 준비 완료로 보지 않는다**. 이전 Q1~Q28 결정은 유지하며 충돌 시 명시된 사용자 결정이 우선한다.

### Q29 — 자발적 Pro 해지
- '구독 해지'는 **다음 카드 정기결제 중단**을 의미. 이미 결제한 이용기간 종료 시점까지 Pro 기능 유지, 이후 자동 Free 전환 및 Q28 직원 즉시 정지.
- 결제 취소/청약철회/환불 요청은 별도 절차로 접수하고 **법정 권리와 PG 계약 조건을 우선**한다. 해지 버튼만으로 미사용 기간 환불 포기 의사로 취급하지 않는다.
- 취소 예약 시각, 마지막 Pro 이용가능 시각, 구독 상태, 해지 처리자를 감사 이력에 저장. 사용자가 해지를 철회하면 유효한 결제수단 상태 및 중복 청구 여부를 확인한다.

### Q30 — Pro 결제 기준일·요금 표시
- **첫 유료 결제 성공일을 월 결제 기준일**로 삼고 매월 같은 일자에 다음 자동결제를 요청. 해당 날짜가 없는 달은 말일에 실행하고 원래 기준일은 보존한다.
- AI 이용량은 Q24대로 **달력월 1일 KST 초기화**. 결제 기준일과 AI 사용량 기준일은 별도로 안내한다.
- Pro 가격 **월 29,000원(가안)**. 고객에게는 부가세 포함 금액으로 표시하는 방향을 채택하되, 실제 가격/부가세 적용/영수증·세금계산서 의무는 출시 전 세무·PG 검증 후 최종 확정.

### Q31 — 정기결제 실패 재시도 세부값
- Q27 유지: 결제 실패 후 **7일간 Pro 유지**, 자동 재시도 **최대 2회**. 권장 재시도 시점은 실패 후 **2일/5일(KST 같은 시각)**, 7일 만료 시 실패 상태면 Free 전환 및 고객 알림.
- 결제 실패 즉시 관리자 이메일/화면 알림 + 카드 변경·수동 재결제 경로 제공. 새 카드로 결제에 성공하면 재시도 작업 중복 실행 금지.
- 카드사 거절 등 재시도로 해결되지 않는 실패는 동일 결제수단 반복을 피하고 갱신 안내. 외부 API 기능·허용 재시도 규격 확인 전 실결제 자동 실행 금지.

### Q32 — 사용량/요금제 변경의 경계 처리
- AI 성공 사용량은 작업 생성 시 KST 달력월에 **1건 예약**, 작업 최종 성공 때 확정하고 실패면 예약 해제. 월말 시작·익월 완료 작업은 **예약한 월에 귀속**, 일련번호/작업 ID로 중복 차감 불가.
- 동시에 실행된 요청은 DB 잠금/유일 제약을 통해 월 한도를 넘지 않도록 한다. AI 응답이 일부만 생성되었고 유효한 전체 분석+초안이 없으면 실패/미차감.
- Free→Pro는 **결제 성공 즉시** 권한 확대. 해당 달 이미 사용한 AI 횟수는 Pro 300건에 **포함**하되 신규 결제 시 사용량을 0으로 초기화하지 않는다. 월 1일에 다음 월 한도 갱신.
- 사용자 자발적 Pro 해지는 Q29대로 결제 기간 말일 Free 전환. 재활성화 시 결제 완료와 좌석 제한·중복 청구를 검증.

### Q33 — 기업 AI 설정/답변 규칙 기본값
- 기업 정보: 소개(최대 2,000자), 주요 서비스(최대 2,000자), 문의 연락처(최대 300자), 답변 말투(정중·간결 **기본**, 친근, 공식적) 제공.
- 초안 재생성은 최초 생성 외 **최대 3회/문의**. 매 재생성은 Q17대로 AI 1건 추가 차감. 직원 수동 편집은 무제한·무료. 기업별 비용·모델 통계는 Q23 운영자 현황판에서 확인.
- AI 분류가 모호하면 '기타'로 분류하되 담당자가 수정 가능. 긴급도는 AI 참고값으로 담당자가 수정할 수 있으며, 고객 문구에 없는 가격·납기는 생성하지 않음.
- 내부 확인사항은 고객 답변과 분리하고 **발송 전 담당자가 각 항목을 확인했음을 체크**해야 발송 가능. 가격·기한·계약 관련 미확인 사항을 단순 무시한 자동 발송 금지.

### Q34 — 계정·초대·운영자 권한
- Q25에 따라 Free 관리자 1명, Pro 관리자 1명+직원 5명. 초대 링크는 **7일 후 만료**, 이메일 기반 1회용·재발급 가능. 추가 좌석/관리자 유료 증설은 초기 출시에서 제외.
- 기업 관리자의 직원 정지와 구독 하향에 의한 정지는 **서로 다른 상태**. Free→Pro 시 과거 요금제 때문에 정지한 직원만 복구하고 관리자 수동 정지는 유지.
- 한 로그인 계정의 다중 기업 소속은 첫 출시에서 지원하지 않으며, CORGLAB 운영자 계정은 기업 관리자와 별도 권한. 운영자 대시보드에서 문의 원문은 기본 비노출.
- 재설정 링크는 30분 만료·1회용. 비밀번호는 안전한 해시로 저장하고 운영 서비스는 안전한 세션 쿠키와 CSRF 방어를 사용.

### Q35 — 이메일·도메인·발신 정책
- 추천 서비스 호스트명은 **desk.corg.app**, Resend 발신 주소는 **notify@desk.corg.app**로 설계. **DNS 소유·실제 사용가능 여부·발신 도메인 인증은 확인 전이므로 배포 완료 표시 금지**.
- 초기에는 CORGLAB 인증 발신 주소 사용(고객사별 자체 이메일 도메인 발신은 후속). **Reply-To는 해당 기업의 검증된 연락처**로 설정하고 인증되지 않은 고객 입력을 발신 주소로 사용하지 않는다.
- 신규 문의 알림과 고객 답변 발송은 작업 큐/발송 이력으로 관리. 사용량 한도/Resend 플랜 제약 시 발송 실패 기록·수동 전환 및 운영자 알림. 무료 한도 충족 여부는 실계정에서 확인.

### Q36 — 문의 위젯 초기 상세
- 고객에게 보이는 우측 하단 버튼+팝업. 기업별 색상/버튼 문구 설정. 기본 문의 필드 **이름·이메일·문의내용 필수 / 회사명 선택**.
- 파일 첨부·필드 추가 편집은 1차 출시 제외. 모바일 대응, 키보드 접근성, 팝업 열기/닫기·포커스 관리, 기존 홈페이지 CSS 충돌 방지 필수.
- 위젯 허용 도메인 검증·스팸 제한·개인정보 수집 고지 및 필수 동의를 구현. 별도 문의 페이지 링크 제공(Q3 유지).

### Q37 — 데이터 보관·삭제·복구
- Q11 유지: 문의 **처리 완료 후 1년** 보관 및 자동 삭제. 처리 완료 시점은 문의 상태가 '완료'로 변경된 시각으로 정의. 삭제 기준일 변경 시 수정·재오픈 이벤트 감사 이력을 남긴다.
- 기업 탈퇴는 **30일간 내보내기 가능**한 유예 상태로 두고 기간 경과 후 삭제(법정 보관 예외). 내보내기는 CSV(문의)와 JSON(상태·이력) 제공. 백업은 최대 30일 보관 후 주기적 폐기하도록 설계.
- 완료되지 않은 장기 미처리 문의의 보존 상한, 법정 의무 예외·정보주체 권리·국외 처리 고지 등은 실제 개인정보처리방침 법무 검증 필요. 개발 전 테스트 데이터로만 검증하며, 동의·삭제 정책 미검증 상태에서 실고객 데이터 수집 금지.

### Q38 — 대시보드·AI 운영 세부값
- 기업 현황판: 월 문의 접수/처리 상태·AI 성공/실패·잔여 AI 건수. 운영자 현황판: 전체 기업별 AI 성공률·실패 코드·모델별 추정 API 비용.
- AI 성공률은 **사용자 요청 단위**(자동 재시도는 한 요청으로 계산)로 집계. 기간 필터는 오늘·7일·30일·달력월을 제공, 금액은 **USD 추정 비용**으로 우선 표시.
- 플랫폼 전사 오류 급증·비용 임계값 자동 알림은 Q23대로 후속 개발. 단, **개별 AI 작업 최종 실패 시 담당자 알림**은 Q22에 따라 MVP에 포함.

### Q39 — 서버 운영 기준
- Oracle Cloud Always Free에서 Docker Compose로 운영 후 부하·메모리 부족/안정성 문제 시 AWS Lightsail 이전(Q14 유지). **계정 홈 리전·무료 인스턴스 가용성·권한은 확보되지 않았음**.
- PostgreSQL은 **매일 자동 외부 백업**, 최근 7일 일간 + 최근 4주 주간 백업, **월 1회 실제 복구 테스트** 권장. 운영 비밀정보는 저장소 밖에 보관하고 HTTPS·방화벽·로그·헬스체크 적용.
- ARM/x86 다중 아키텍처 이미지·PostgreSQL 백업 복원·DNS 전환 문서 준비. 실제 운영 도메인/리전/백업 저장소 및 요금은 가입·생성·DNS 인증 후 확정.

### Q40 — 법무·과금 확인 및 릴리스 기준
- 초기 환불 처리: 중복 청구·명백한 결제 오류는 신속 처리하고, 그 외 환불 요청은 **법정 청약철회/환불 권리 및 약관** 검토 후 처리. 법무 검증 전 '환불 불가' 같은 단정적인 약관이나 자동 환불 정책을 게시하지 않는다.
- 사업자·카드 매출 증빙·부가세 신고 및 이용약관·개인정보처리방침·Resend/OpenAI 개인정보 처리 사항은 실제 판매 전 확인.
- **실제 출시 차단 항목**: 토스페이먼츠 정기결제 계약·운영 승인, Resend 발신 도메인 인증, HTTPS, 권한·기업별 데이터 격리, 개인정보/법무 정책, DB 백업 복구 검증, 배포 서버 실제 가용성 및 통합 테스트.
- 이 장은 정책 합의·기본값 채택이며 **기능 구현·실제 서비스 배포·대외 검증 완료를 의미하지 않는다**.
