# CORGLAB Desk — Product Requirements Document (PRD) v1.0
- 확정일: 2026-11-10
- 상태: Q1~Q8 제품 방향 확정 / 일부 운영 세부사항 미결정
- 저장소: https://github.com/webcorgi/corglab-desk
- 목적: 포트폴리오 실습이 아닌 실제 판매 가능한 B2B 구독형 SaaS
- 문서 원칙: **확정 사항**, **설계 권장안**, **미결정**을 구분한다.

## 1. 제품 정의
홈페이지를 운영하는 기업이 기존 홈페이지에 문의 위젯을 삽입하거나 전용 문의 페이지를 연결하고, 들어온 고객 문의를 AI로 분류·요약하여 직원이 답변 초안을 검토·승인한 후 이메일로 응답하는 고객 문의·견적 관리 SaaS.

### 타깃·가치
- 타깃(확정): 홈페이지를 운영하는 모든 기업(코그랩 제작 고객 포함).
- 가치: 문의 누락 감소, 담당자 처리 시간 단축, 문의 이력 및 처리 현황 확인.
- 1차 제품: AI 문의·견적 관리.
- 후속 확장: AI 실시간 상담, 상담원 연결, 견적·계약 관리.

## 2. 기획 인터뷰 결정 기록 (확정)
| ID | 결정 영역 | 확정 내용 |
|---|---|---|

| Q3 | 설치 | 홈페이지 설치용 스크립트 코드 + 기업별 전용 문의 페이지 링크. 직접 API 연동은 후속 |

| Q8 | 배포 | 클라우드 VPS + Docker |

## 3. 사용 흐름 (MVP)
1. 기업 관리자 가입 → 기업 생성 → 홈페이지/도메인 등록.
2. 위젯 코드 복사 또는 기업 전용 문의 페이지 URL 발급.
3. 홈페이지 방문자가 이름·이메일·문의 내용을 제출; 회사명은 선택.
4. 서버 입력 검증, 스팸 방어, 기업 연결 확인, 월 사용량 한도 적용 후 문의 저장.
5. AI가 문의 카테고리·요약·답변 초안을 생성. AI 장애 시 문의는 보존하고 재처리 가능.
6. 관리자/직원에게 화면·이메일 알림.
7. 직원이 답변 초안을 수정해 제출. 명시적 승인 및 발송 액션 후 고객 이메일 전송.
8. 발송 성공/실패, 시각, 담당자, 상태, 처리 이력 및 사용량을 기업 단위로 조회.

### 사용자·권한 (확정 범위)
- 방문자: 공개 폼으로 문의 등록; 타 고객 정보 조회 불가.
- 관리자: 기업 설정, 도메인/설치 코드 관리, 직원 초대·권한 관리, 모든 기업 소속 문의 조회·처리.
- 직원: 자신이 속한 기업의 문의 조회·상태변경·답변 작성/승인/발송. 기업 설정 및 직원 초대 불가.
- 한 사용자의 복수 기업 소속 지원 여부는 현재 설계 권장 사항이며 별도 확정 필요.

## 4. MVP 필수 기능과 완료 기준
| ID | 기능 | 완료 기준 |
|---|---|---|
| F01 | 기업 가입·로그인·초대 | 기업 가입, 관리자 생성, 만료 있는 직원 초대, 로그인/로그아웃·권한 분리 |
| F02 | 테넌트 격리 | 모든 조회·수정·발송·할당량에서 로그인 사용자의 소속 기업으로 범위 제한; 다른 기업 접근 차단 테스트 |
| F03 | 설치 코드·링크 | 기업별 위젯 설치 스크립트와 별도 문의 링크 제공. 허용 도메인 검증. 위젯 식별자는 비밀키로 취급하지 않음 |
| F04 | 문의 접수 | 필수 필드 유효성, 개인정보 안내 및 필수 동의(정책 확정 후), 중복/스팸 제어, DB 저장 |
| F05 | AI 처리 | 분류·요약·답변 초안. 실패 시 재시도/상태 확인, 고객에게 자동 발송하지 않음 |
| F06 | 문의 관리 | 목록·상세·검색/필터·상태·담당자·이력, 페이지네이션 |
| F07 | 알림·발송 | 신규 문의 이메일/화면 알림, 담당자 승인 후 고객 이메일, 실패 재시도 및 발송 이력 |
| F08 | 요금/한도 | 무료 월 30건 사용량 집계 및 초과 정책 구현(초과 정책 확정 전 출시 불가), 유료 구독 구분 |
| F09 | 운영 | HTTPS, 안전한 비밀정보 관리, DB 백업·복구 검증, 모니터링/로그, CI/CD, Docker 운영 |
| F10 | 사용자 검증 | 외부 기업 1곳 이상 온보딩, 실제 위젯 접수→AI→담당자 승인→이메일 발송 확인 |

## 5. 1차 출시 범위에서 제외
- 실시간 AI 챗봇/AI 대화형 고객 상담
- AI가 독자적으로 이메일 자동 발송
- 견적서 발행·전자계약·일반 CRM 전체 기능
- Slack, 카카오 알림톡, Discord, 외부 웹훅, 개발자 직접 API 연동
- 부서·팀별 세밀한 권한, 외주 협력사 접근

## 6. 기술 아키텍처 (설계 권장안, 현재 저장소 기반)
- 프론트: React 19 + Vite / 관리자 웹 + 임베드 문의 위젯 + 별도 호스팅 문의 페이지
- API: Java 21 + Spring Boot 3.5 + Spring Security + Bean Validation
- DB: PostgreSQL 17 + Flyway SQL 마이그레이션
- 비동기: Redis 기반 작업 큐 또는 DB outbox + 워커 (구현 및 라이브러리 결정 전)
- AI: OpenAI API 서버 호출(모델·비용 상한 설정 가능하도록 분리)
- 이메일: 공급업체 미정; 발송 이력/재시도/중복 방지 필요
- 인프라: 클라우드 VPS + Docker Compose + 리버스 프록시 + HTTPS + 비밀값 환경변수/시크릿 저장
- CI/CD: GitHub Actions, 단위/통합 테스트 후 이미지 빌드·배포
- 데이터 보안: 인증 사용자의 기업 소속을 서버에서 조회(클라이언트 tenant_id 신뢰 금지), 모든 DB 쿼리 기업 단위 제한, 권한 테스트, 접근 기록 최소화
- **현재 저장소 코드 상태:** 로컬 개발용 Basic 인증, 단일 설정 tenant_id, 기초 문의 폼/API/분류; 다중 기업 SaaS, 위젯, 초안, 알림, 결제, 실제 배포는 미완료.

### 핵심 엔터티 (권장안)
organizations, users, memberships(role), invitations, domains, inquiry_forms, inquiries, inquiry_events, ai_jobs, draft_replies, outbound_emails, notifications, plans, subscriptions, usage_counters.
명확한 FK/인덱스, 타임스탬프, 상태 열거, 전송 중복 방지 키를 설정. 실제 스키마는 기능 구현 시 확정.

## 7. 비기능 요구·출시 차단 조건
- 운영용 로그인·권한 관리(개발용 Basic 인증 금지), 세션/CSRF 정책 및 비밀번호 재설정
- 기업 간 교차 접근·직원 권한 상승 방지 테스트
- 공개 문의 폼 Rate Limit/CAPTCHA 등 스팸 방어, CSRF/CORS/도메인 검증
- 개인정보 수집 동의·보유 기간·삭제/열람 절차·AI 공급업체 처리 안내 확정
- AI 프롬프트 인젝션 방어: 고객 입력은 신뢰하지 않음; 생성 결과는 사람이 승인
- 발송 큐·멱등성·재시도 한도·실패 알림; AI/메일 장애 시 문의 데이터 유실 방지
- 백업과 실제 복구 테스트, HTTPS, 감사 로그, 장애 알림
- DB 변경은 버전 관리; 기존 데이터가 있을 경우 안전한 이관 검증
- 테스트 실패 또는 위 조건 미충족 시 실제 고객 데이터 수집을 시작하지 않음

## 8. 요금·사업 (확정과 가안 구분)
- 확정: Free + Paid 2단계로 출발.
- 확정: 무료 한도는 기업 기준 **월 문의 30건**.
- 가안: 유료 월 **29,000원부터**, 실제 판매가·세금 포함 여부·프로 직원 수/AI 한도 등은 미결정.
- 유료 구독을 제공할 예정이나 자동 결제(PG) 도입 시점과 최초 수동 결제 방식은 미결정.
- 검증 지표 권장: 신규 가입→설치 완료율, 문의 처리율/평균 시간, AI 초안 채택률, 무료→유료 전환, 문의당 AI·메일 원가.

## 9. 개발 단계 (완료 기준 기반, 기간 확정 아님)
### M0 — 기초 품질·배포 준비
CI runner 오류 확인, Java 21 빌드, Docker 통합 검증, Flyway/DB 이관 정비, 주요 테스트 구축.
완료: 신규 환경에서 한 명령으로 구성하고 API/DB 동작 확인.

### M1 — 기업·계정·보안
기업 가입, 관리자/직원, 초대, 운영용 인증 및 권한, 서버 측 소속 기업 매핑, 테넌트 격리 테스트.
완료: A사 계정으로 B사 문의/API 접근 불가, 초대·로그인·로그아웃 사용 가능.

### M2 — 설치와 문의 접수
기업별 전용 문의 링크, 위젯, 도메인 설정, 문의 폼·동의, 스팸 방지, 한도 집계.
완료: 두 개 서로 다른 도메인의 테스트 홈페이지에서 각 기업에 문의 정확히 적재.

### M3 — AI 및 담당자 워크플로
AI 분류/요약/초안, 관리자 알림, 승인 플로우, 이메일 작업 큐·재시도·이력.
완료: 문의→AI 초안→직원 승인→메일 발송 및 실패 복구까지 확인.

### M4 — 유료화·운영·시범 출시
Free/Pro 한도, 결제 정책 구현, HTTPS/CI/CD/모니터링/백업, 개인정보 정책, VPS 배포, 실제 파일럿 기업.
완료: 외부 테스트 기업이 설치 후 실제로 문의 처리; 운영 테스트·보안 점검 통과.

## 10. 미결정 사항 (확정 Q1~Q8과 구분)
1. 업체명·서비스 도메인·VPS 사업자/리전·월 예산·운영자 연락처
2. 유료 구독의 정확한 제공량, 직원 수/AI 사용량 제한, VAT 포함 여부, 요금 갱신·환불 정책
3. 무료 30건 초과 시 차단/대기/자동 유료 전환 중 처리 방식과 월 집계 기준(달력월/가입일)
4. 수동 청구 vs PG 자동결제, 영수증/세금계산서 처리 방식
5. 이메일 발송업체와 발신 도메인, 발송량 제한
6. 관리자/직원 초대·재설정·복수 조직 소속, 승인권자 지정 세부 기준
7. 위젯의 UI(팝업/인라인), 필드 커스터마이징, 파일 첨부 여부
8. 개인정보 보존·삭제 기간, 동의 문구, DPA/제3자 국외 이전 등 법무 검토
9. 고객별 AI 프롬프트/답변 어조, AI 사용량 상한, 사람 승인 UX
10. 실시간 AI 상담 기능의 2차 출시 우선순위

미결정 사항은 개발 시작을 모두 막지 않음. 단, 요금 초과 정책·개인정보 처리·발송 정책·보안은 상용 출시 이전 확정 필수.
